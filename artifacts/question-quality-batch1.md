이 문서는 학습 효과나 정답률을 측정한 결과가 아니다. 기존 로드맵의 약 49%는 **표본 10문항에 대한 주관적 편집 평가**이며, 같은 평가표를 다시 적용한 값도 편집 점수다. 실제 풀이 통계(정답률·변별도)는 아직 없다.

## 1. 수정한 파일과 기능

### 데이터 보호 (`d0d1a87` 이식)

현재 브랜치(`7e2ec47`)에는 해당 커밋이 없었으므로, 디자인 개편 코드에 맞춰 이식했다. v3 UI 문구를 전제로 한 `CardsPage` RTL은 가져오지 않았다.

| 동작 | 구현 |
|---|---|
| 손상된 백업 거부, 기존 데이터 보존 | `backupValidate` 중첩 검증, restore 실패 시 DB 유지 |
| 콘텐츠 업데이트 시 세션·메모 보존 | `ensureSeeded`에서 `activeSession.clear()` 제거 |
| 다른 시대 복습 카드도 시작 | 복습 세션이 `pickDueCardsForToday`로 due 카드를 고름 |
| 복습만으로 오늘 정규 학습 완료 처리하지 않음 | `finishSession`에서 review-only는 `completed: false`, 단원 완료 미기록 |
| 모의고사 저장 실패 시 답안 보존·재시도 | `createProgressSaver.flush`가 실패를 던지고, 제출·닫기는 catch 후 시험 유지 |
| 구버전 백업의 단원 완료 복원 | v1은 `studyDays`에서 `lessonCompletions` 재구성 |

### 문항 관리 구조

- 용도 `practice` / `mock`
- 검수 `draft` / `in-review` / `approved` / `retired`
- 내용 버전, 사실 출처, 제작 방식, 검수 주체·일시, 자료 이용 조건
- 출제 유형·자료 유형·추론 단계
- 배점(`difficulty`)과 풀이 통계(`stats`) 분리
- 기본값: 기존 100문항은 `draft`, AI/사람 검수 없음, 이용 조건 `unverified`, 유사도 `not-run`
- 1차 10문항은 `in-review` + `reviewAgent: ai`. **승인으로 기록하지 않음**
- 승인 조건은 `src/lib/questionReview.ts`. AI 검토만으로는 승인 불가
- 실전 50문항: 승인 문항이 50개 미만이면 검수 전 문항을 쓰되, 연습 모드와 구분하는 안내를 띄움. 몰래 승인된 것처럼 채우지 않음
- 생성된 시험은 `QuestionSnapshot`에 줄기·선지·정답·해설·자료·버전을 고정. 은행을 고쳐도 진행 중·과거 시험의 문항이 바뀌지 않음

### 출제 비율 근거 데이터

- 대상: 공식 심화 65~79회 750문항
- 실제 확보: 공식 원문·문제지 이미지는 저장소에 없음. 완료 태깅 0문항. 79회 편집 비교용 측정 방식 10건만 `outline-only`
- 자동/편집 태그는 추정값. 미분석 문항을 분석 완료로 세지 않음
- 가중치(`recentWeight`, `previousWeight`)는 설정 가능. 태깅이 없으면 임시 목표만 반환하고 **공식 출제 비율이라고 표시하지 않음**
- 확인된 값: 77~79회 정답표 기준 1점 10 · 2점 30 · 3점 10
- 전근대 61% · 근현대 39%는 임시값
- 재고가 모자라면 시대·배점·유형 부족을 보고하고 `__pad`로 채우지 않음

### 출제·저장

- `balanceAnswerPosition(..., index % 5)` 제거. 일일 학습용 은행은 문항 ID 기반 시드로 한 번만 선지를 섞고, 모의고사는 생성 시 다시 섞어 스냅샷에 고정한다. 시간순 선지는 섞지 않는다. 위치별 개수를 맞추지 않는다.
- 선지 섞기와 정답 인덱스를 함께 변환해 스냅샷에 저장
- 시간순·배열형(`choiceOrder: 'keep'`)은 섞지 않음
- 정답 위치를 같은 개수로 맞추거나 새 순환 규칙을 넣지 않음

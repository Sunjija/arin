# P1-03 · 복습 이유·풀이 이력 통합 검증

2026-09-11. 통합 브랜치 `codex/arin-design-v3`. 시작 기준 `d1c17511201505766db8ab161af9f0f4940602c4`, 공유 API `afe60756ddb64fda1ee3613dce9915af4763ee47`, 백업 검증 `0b60501`, Cursor UI 제출 `c4feb4ea4f06deea2bf1b1c52ffd87f4078f2215`, 반입 `db8823f`. 아래 결과는 총괄 보완을 포함한 이 문서와 함께 커밋한 소스 기준이다. GitHub 푸시·CI와 공개 배포를 별도로 확인한다.

## 이번에 완료한 범위

- 문제마다 오늘 개념 확인 / 단원 확인 / 복습 예정일 도래 / 최근 오답 / 배운 범위 확인 중 실제 선정 이유를 저장하고 문제·해설에서 표시한다.
- 최근 오답은 선정일을 포함한 최근 7개 로컬 달력일의 마지막 답안을 기준으로 한다. 이후 정답을 제출한 문항은 새 계획의 최근 오답 우선 대상에서 제외한다. 과거 답안은 보존한다.
- 도래 문항 후보는 일일 카드 상한 전의 학습된 도래 카드에서 얻는다. 도래 우선 배정 뒤 남은 도래·최근 오답·배운 범위 순서로 채우며 새 문항과 중복하지 않는다.
- 동일 문항의 기존 답안 수를 세션 시작 때 고정한다. 첫 풀이 / 다시 풀이 / 구분 정보 없음의 정답·문항 수를 결과에서 분리한다. 명시적 계열 매핑이 없으면 유사 문항 노출은 미확인이다.
- 카드가 없어도 복습 문제가 있으면 시작할 수 있다. 완료된 복습 결과는 새로고침·날짜 변경에도 유지하며 목록의 명시적 시작만 새 회차를 만든다. 미완료 학습은 먼저 재개한다.
- 결과 전체와 그룹 집계 모두 중복 questionId를 제거한다. 0문항 그룹은 기록 없음이며, 첫 풀이를 실전 실력이나 처음 보는 자료로 해석하지 않는다.

## 역할과 통합 검수

Cursor에는 QuizStep·ResultStep과 관련 테스트·보고서 5파일만 맡겼다. 허용 경계를 준수했고 독립 UI 테스트 8개와 타입/lint를 제출했다. [실제 전달 지시](cursor-tasks/2026-09-11-review-context.md), [제출 보고서와 총괄 보완](reviews/p1-review-context-ui.md)을 보관한다.

총괄은 선정·세션·백업 계약을 먼저 만들고, 반입 후 단위가 없던 결과 분수와 중복 합산을 보완했다. 브라우저에서 발견한 카드 0장 복습 진입 누락 및 결과 새로고침 시 자동 새 회차 시작도 수정했다. 기존 #12의 별도 DailyLearningService/StorageAdapter는 추가하지 않고 현재 learningApi/studyService를 확장했다. #6의 동일 attempt 원인 갱신 경로도 유지한다. 무검수 자동 병합 가능한 품질이라는 평가는 하지 않는다.

## 자동 검증

설치된 Node로 아래 명령을 실행했다. 의존성이나 잠금파일 변경은 없다.

|---|---|
| `node node_modules/vitest/vitest.mjs run` | **239 passed / 49 files**, 실패 0 |
| `node node_modules/typescript/bin/tsc -b --pretty false` | exit 0 |
| `node node_modules/oxlint/bin/oxlint src` | exit 0 |
| `node node_modules/vite/bin/vite.js build` | 성공, JS 637.72 kB / gzip 195.88 kB |

Sites 빌드 도우미도 실행했지만 기존 npm/pnpm 잠금파일이 공존하여 관리자 판정 단계에서 중단되었다. 두 파일을 임의 삭제하지 않았으며 기존 CI의 TypeScript/Vite 빌드를 위와 같이 직접 검증했다. 기존 번들 500 kB 초과 경고와 콘텐츠 출처·검수 경고는 남아 있다. 구조 검사 통과를 역사 사실 검수나 실전 난이도 승인으로 간주하지 않는다.

이번에 추가한 검증은 선정·날짜·이력·결과 재개 8개, 백업 4개, Cursor UI 8개, 복습 진입 3개다. 기존 마이그레이션 fixture가 구형 자료에 새 context를 잘못 남긴 부분도 수정하여 실제 구형 필드 부재를 재현했다.

## 데이터·호환성과 남은 일

정책 버전은 `learning-foundation-v3`, DB/백업은 v4다. 새 context는 선택적이며 구형 v1~v4 백업에 필드가 없으면 미확인으로 보존한다. 필드가 있으면 문항 범위·중복·이유·날짜·횟수를 쓰기 전에 검사하고 손상 자료는 기존 DB를 그대로 둔 채 거절한다. 선정 이유는 고정 계획을 만들 당시, 이전 답안 수는 세션 시작 당시 기준이다. 매 답안 제출마다 당일 계획을 다시 선정하는 정책은 아니다.

- 개인별 실측 가중치, 회상/비교/새 자료의 유형 배분, 문항 계열 전체 매핑은 남아 있다.
- 설명 7/88개, 명시적 개념 연결 8/102문항, 실제 이미지 문항 0개, 실측 난이도 문항 0개다. 전 범위 시험 대비가 완료된 상태는 아니다.
- 다음 구현 순서는 오늘 학습 다중 창 충돌 방지 → P1-05 기록 지표 → P1-06 첫 단원 통합 검증이다. [로드맵](development-roadmap.md)의 다음 묶음은 아직 새로 배정하지 않았다.
- 기존 Sites 프로젝트를 native get_site로 재조회했으나 404였다. 공개 배포는 미완료이며 기존 계정·워크스페이스의 Sites 접근 복구가 필요하다. [배포 상태](deployment-status.md)를 따른다.

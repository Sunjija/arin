# 한사코치 개발 로드맵

기준일: **2026-09-11**. 이 문서는 앞으로 할 일의 우선순위·의존성·완료 기준을 관리하는 원본이다. 정책은 [공통 계약](parallel-redesign/contracts.md), 수정 경로는 [소유권](parallel-redesign/ownership.md), 역할별 실행 지시는 [작업 안내](parallel-redesign/README.md)를 따른다.

**다음 목표는 선사·고조선 한 단원을 목표 설정 → 개념 이해 → 확인 문제 → 누적 복습 → 기록 확인까지 완주할 수 있게 만드는 것이다.** 이 흐름을 검증한 뒤 전 범위 콘텐츠와 실전 평가를 확장한다. 새 화면 수나 문항 총량만 늘리는 것을 완료로 보지 않는다.

이 문서는 계획이며 새 작업을 실제 배정하거나 에이전트를 실행한 기록이 아니다. 담당은 권장 역할이다. 시작할 때 최신 원격 SHA와 관련 PR을 다시 확인한다.

## 2. 우선순위와 실행 순서

- **P0 — 먼저 해결:** 기존 PR 통합 판단, 콘텐츠 지도, 공통 계약·기록 보존, 첫 단원 학습 원본.
- **P1 — 첫 출시 묶음:** 목표와 일일 분량, 개념 우선 학습, 누적 복습, 자료실 기록 통합, 한 단원 전체 검증.
- **P2 — 학습 서비스 완성도:** 기출 분석, 전 범위 설명·문항·이미지, 실전 평가, 실제 학습 효과 검증.
- **P3 — 그다음 확장:** 계정 동기화, 모바일 앱, 결제, 정교한 개인화. 기존 PR은 보존하고 재검수한다.
- **Q — 계속 유지:** 기존 자동 검사의 데이터 구조 대응과 문서·운영 상태 관리. 이미 설치한 자동화를 다시 만드는 일이 아니다.

상태: **착수 가능** = 조사·작성을 시작할 수 있음, **선행 대기** = 표의 의존성 완료 후 구현, **후순위** = 앞 단계 결과를 보고 범위 결정. 어느 상태도 작업 배정을 뜻하지 않는다.

### P0-02 · 데이터가 얼마나 부족한지 개념 단위로 산출하기

산출물: `docs/content-coverage.md` 및 재집계 가능한 목록(추가 예정). 시대 → 단원 → 개념 → 설명/확인 문제/복습/실전 문항/이미지/출처/검수 상태를 연결한다.

- 18개 단원명만으로 전 범위 충족을 판단하지 않는다. 여러 나라, 가야, 시대별 정치·경제·사회·문화와 사건 연결이 독립적으로 학습 가능한지 점검한다.
- 기준 브랜치 문항 수는 선사 6, 삼국 8, 남북국 7, 고려 15, 조선 전기 6, 조선 후기 12, 개항 11, 일제강점 14, 현대 14, 문화 7이다. 적은 영역부터 확인하되 개념·유형별 공백을 최종 보충 기준으로 삼는다.
- **완료 기준:** 모든 기존 데이터에 유지/수정/보충/검수 대기 상태가 있고, 필수 개념별 부족량·필요 자료·우선순위가 드러난다. 문항 총량 목표는 이 결과로 산정한다.

### P0-03 · 공통 계약·기록 보존·계획 엔진

산출물: 기존 PR 타입 매핑표, 구현된 서비스 API와 소비 예제, DB/백업 이전, 관련 회귀 검증. [E brief](parallel-redesign/briefs/E-learning-foundation.md)를 따른다.

- 목표·개념·문항 버전·시도·진도·복습 도래일·세션 모델을 기존 코드와 조정한다. `difficulty`의 배점 의미와 실측 난이도를 분리하고 문항 계열·노출 기록을 수용한다.
- 오늘 학습/자료실/복습이 같은 답안 기록 경로를 사용한다. 날짜 기반 진도와 완료 기반 진도를 분리한다. 기존 기록에서 개념 학습 여부를 확정할 수 없는 경우의 이전 규칙을 명시한다.
- **완료 기준:** 기존 카드 편집·오답·완료 이력·진행 세션·모의 답안·구형 백업이 보존된다. 재개·중복 제출·저장 실패·실패한 가져오기 시 DB 불변을 검증한다. 실제 export와 에러 계약 확정 뒤 B/C/F가 소비한다.

### P0-04 · 선사·고조선을 설명부터 학습할 수 있게 만들기

산출물: JSX에 흩어진 설명을 옮긴 재사용 가능한 학습 원본과 검수 기록.

- 개념별로 배경·변화 이유 → 특징과 비교 → 대표 자료 → 확인 문제 → 선지별 해설을 연결한다. 구석기/신석기/청동기/철기와 고조선을 학습 목표에 맞게 나눈다.
- “개념을 설명해보세요” 같은 단독 지시를 “어떤 대상을 어떤 관점에서 답해야 하는지” 드러나는 질문으로 수정한다. 자유 회상은 기대 답안·핵심 요소·자가 확인 기준을 함께 제공한다.
- **완료 기준:** 처음 보는 학습자가 문제의 정답 근거를 앞선 설명에서 찾을 수 있고, 문제의 단원/개념 연결과 사실·출처를 검수한다. 현재 6문항은 출발점이며 수량 자체를 충분성 기준으로 삼지 않는다.

### P0-05 · 기존 공개 배포 경로 복구

- 기존 `.openai/hosting.json`의 Site와 연결 계정·워크스페이스를 확인하고 접근 오류를 해소한다. 연결이 막히면 필요한 사용자 조치와 오류를 기록한다.
- **완료 기준:** 배포 담당이 빌드 SHA·배포 ID·공개 URL·직전 정상 버전을 추적할 수 있고 공개 전 검증/복구 절차가 있다. 실제 최신 앱 배포는 P1-06에서 수행하고 GitHub 푸시와 별도로 확인한다.

## 4. P1 — 한 단원에서 학습 흐름 완성

### P1-01 · 목표 설정과 현실적인 하루 공부량

- 목표 급수, 시험 회차/직접 입력/미정, 학습 경험, 학습 요일을 받고 **시험일·개념 완주일·최종 복습 기간**을 구분한다. 공식 일정에는 출처와 확인일을 저장하고 사용자 목표일을 자동 덮어쓰지 않는다.
- 하루 분량은 개념·확인 문제·도래 복습 개수로 제시한다. 고정 120분이나 카드/문항당 임의 예상 시간을 학습 약속에서 제거한다. 실전 시험 타이머는 유지한다.
- **완료 기준:** 결석·날짜 변경·목표일 변경에도 미완료 개념을 건너뛰지 않는다. 미정/과거 시험일, 학습일 부족, 복습 누적을 처리하고 실제 남은 분량을 보여준다. 사용자가 관찰한 10분을 모든 사용자의 완주 시간으로 일반화하지 않는다.

### P1-02 · 개념 우선 세션과 정확한 출제 범위

- 신규 학습은 설명 → 비교/자료 → 확인 문제 → 피드백 순서로 진행한다. 새 문제는 현재 개념/단원에 연결된 검수 문항에서 고른다. 풀이 중단 뒤 같은 단계로 재개한다.
- 선사·고조선에서 다른 시대의 **새 문제**가 섞이지 않게 한다. 후보가 부족하면 분량을 줄이거나 준비 중 상태를 표시한다. 시대가 같다는 이유로 미학습 개념 문제를 채우지 않는다.
- **완료 기준:** 첫 사용자, 재개 사용자, 문항 부족, 자료/이미지 누락, 정오 피드백과 중복 클릭을 검증한다. 버튼 연타·새로고침이 답안 이력을 늘리지 않는다.

### P1-03 · 반복 학습을 취약 개념 중심으로 바꾸기

- 복습은 **이전에 배운 전체 시대**에서 도래일·오답·어려움 표시·최근 노출을 고려한다. 오늘의 새 단원 필터와 복습 필터를 분리하고 출제 이유를 표시한다.
- 같은 정답의 반복 노출만 늘리지 말고 회상·비교·새 자료 적용을 섞는다. 오답 뒤 보충 설명을 제공하고 재확인한다. 같은 항목 독점과 누적 복습 과부하를 제한한다.
- **완료 기준:** 미학습 개념은 자동 복습에 들어가지 않고, 예전에 틀린 다른 시대 개념은 다시 나온다. '최근 오답'과 '복습 도래'를 구분한다. 일반 학습의 15/30초 일괄 속도 감점을 제거/전환하고 반복 정답과 새 자료 적용 성과를 분리한다.

### P1-04 · 자료실 가독성과 학습 기록 통합

- 개념은 학습 순서·배경·비교·확인 문제를 구분해 읽도록 구성한다. 긴 제목, 시대 탭(선사·고조선/여러 나라/삼국/남북국), 연표 글자와 모바일 폭을 실물 화면에서 확인한다.
- 오늘 학습과 동일 콘텐츠·기록 서비스를 사용한다. 단순 열람과 학습 완료를 구분하고 자료실 오답을 누적 복습에 연결한다. 검색·시대 이동·뒤로 가기·키보드 초점·`/timeline` 호환을 보존한다.
- **완료 기준:** 자료실에서 답한 뒤 새로고침해도 기록이 남고 오늘/내 기록에 일관되게 반영된다. 320/375/768px 및 데스크톱, 200% 글자 확대에서 겹침·버튼 잘림·본문 가림을 점검한다.

### P1-05 · 진도와 실제 학습 성과 표시

- 목표 대비 완료 개념, 오늘의 남은 분량, 복습 도래, 취약 개념과 판단 근거를 보여준다. 개념 완료율·반복 정답률·미노출 정답률을 혼합하지 않는다.
- 최소 측정 항목: 시작/완료/중단 단계, 다음 학습 재방문, 지연 복습 성공, 문항 계열 노출, 오답 원인(선택), 분량 조정. 응답 시간은 선택 측정이며 미측정은 null로 둔다. 개인정보나 외부 분석 SDK를 이 작업에 임의 추가하지 않는다.
- **완료 기준:** 중복 제출이 지표를 부풀리지 않고 표본 부족은 미측정으로 표시한다. 근거 없는 합격 확률·안정권·과장된 학습 시간을 노출하지 않는다.

### P1-06 · 파일럿 공개 전 통합 수용 검사

- 빈 DB/기존 DB에서 목표 설정 → 첫 개념 → 문제 → 중단·재개 → 자료실 추가 학습 → 다른 날 복습 → 내 기록 → 백업/복원을 검증한다. 시간 이동은 고정 시계 테스트로 재현한다.
- 검증 보고서에 기준 SHA, 데이터 버전, 실행한 화면·기기, 수용 기준별 결과, 미해결 결함을 기록한다. 타입·lint·관련 회귀·빌드 및 자동 감사 통과 후 공개한다.
- **완료 기준:** 기록 손실·중복 답안·잘못된 출제 범위·진도 건너뛰기·읽기 불가능한 UI가 해결되고, 공개 URL에서 배포 버전과 핵심 동작을 확인한다. 파일럿 범위를 표시하며 전 범위 시험 대비 완료라고 표현하지 않는다.

## 5. P2 — 콘텐츠와 실전 신뢰도

### P2-01 · 기출을 분석해 출제 기준표 만들기

- PR #11의 회차 65–79 수집/분석 범위·누락·원본 출처·재현성을 확인하고 최신 공개 회차까지 보충 필요성을 조사한다. 회차 숫자만으로 최신·완전하다고 판단하지 않는다.
- 시대·개념·출제 목적·자료 형태·배점·선지 함정·필요 추론을 분류한다. 자동 추출 결과를 원본과 표본 대조하고 오류율·검수 범위·미확인을 기록한다.
- **완료 기준:** 공식 출처로 돌아갈 수 있는 분석표와 자체 출제 기준이 있다. 분석용 원본, 학습용 자체 문항, 평가용 미노출 계열을 구분한다. 기출 문장/사진을 임의 복제하는 생성 과정으로 만들지 않는다.

### P2-02 · 선사부터 현대까지 설명 과정 확장

- P0-02 공백 목록과 파일럿 결과 순서로 단원을 확장한다. 여러 나라 → 삼국/가야 → 남북국 → 고려 → 조선 → 근현대의 선후 관계와 사회·경제·문화 흐름을 연결한다.
- 문화사를 각 시대의 문화재·종교·생활에 연결하고 마지막에 시대 간 비교를 제공한다. 기존 `culture` ID·이력을 삭제하지 않고 시대/주제 관계를 이전한다.
- **완료 기준:** 출시 대상으로 선언한 모든 필수 개념에 설명·비교·확인·복습 경로와 출처가 있다. 아직 없는 내용은 준비 중으로 표시하고 완료 처리하지 않는다. 단원별 검수 후 점진적으로 제공한다.

### P2-03 · 자체 문항 제작과 편집 검수

- 제작 순서: 출제 기준 → 새 상황/자료·정답 근거 → 그럴듯한 오답과 각 선지 해설 → 개념·계열·버전 연결 → 자동 검사 → 사실·정답 유일성 검수 → 승인된 문항만 배포.
- AI 초안에는 원자료 출처·작성 이력·미확인 사항을 남긴다. 설명을 그대로 반복한 문항과 새로운 자료 적용 문항을 구분한다. 유사 문항을 다른 ID로 바꿔 독립 평가로 세지 않는다.
- **완료 기준:** 초안/검수 대기/승인/수정 필요 상태가 앱 출제 가능 여부와 연결된다. [문항 검수 지침](../agents/question-inspector.md)을 적용하고, 목표 개념/출제 유형별 공백 해소를 확인한다. 자동 통과를 역사 전문가 검수로 표기하지 않는다.

### P2-04 · 문제 자료와 서비스 이미지 제작

- 시험 식별용 유물·문화재는 이용 조건을 확인한 실제 사진을 우선한다. 사료·지도·표는 근거·가독성·모바일 확대를 검증한다. 형식 태그만 '지도'인 텍스트 문제를 실제 지도 문항으로 집계하지 않는다.
- 브랜드 캐릭터·빈 상태·보상·설명 일러스트는 일관된 스타일의 **투명 배경 PNG**를 제작한다. 단색 배경 제거 방식을 쓸 경우 테두리 색 번짐·반투명 부분을 검수한다. 지도·도식·연표는 정확성과 확대가 필요한 경우 SVG/코드 표현을 유지한다.
- **완료 기준:** 자산별 출처/제작 방식/이용 조건/재현 표시/대체 텍스트/검수 상태를 관리한다. 생성 이미지를 실제 유물의 증거로 사용하지 않는다. 렌더링 실패와 이미지 용량도 점검한다. 장식 에셋 증가는 핵심 학습·실전 자료보다 후순위다.

### P2-05 · 실제 시험에 가까운 모의 평가

- PR #8을 검수해 자료 렌더링·문항 관리·출제 기준을 연결한다. 현재 50문항/80분 구조와 10문항 연습을 구분하고, 시험 운영 규정은 구현 시 공식 자료로 다시 확인한다.
- 검수 문항의 시대·주제·자료형·출제 목적 분포를 기준으로 구성한다. 문항 부족 시 실전 생성 불가/연습 상태를 제공한다. 동일 ID 반복과 유사 계열을 이용한 분량 채우기를 금지한다.
- **완료 기준:** 문항 50개 고유성, 배점 합계, 타이머·자동 제출·재개·제출 멱등성·스냅샷 보존을 검증한다. 학습에서 본 문항/계열과 미노출 성적을 구분하고 출제 기준 충족 상태를 표시한다. 배점 분포를 검증된 난이도로 설명하지 않는다.

### P2-06 · 이해·암기 비중과 난이도를 실제 사용으로 검증

- 처음은 이해, 다음은 회상·비교, 마지막은 미노출 자료 적용에 비중을 두되 고정 비율을 효과가 입증된 값처럼 제시하지 않는다. 반복 학습은 기능으로 채택하고 효과는 지연 회상과 실전 전이로 확인한다.
- 파일럿부터 분량 적절성·중도 이탈·다음 날 회상·같은 오답 재발을 관찰한다. 실전 단계에서는 첫 노출 정답률, 오답 선지 선택, 표본 크기, 문항-총점 관계 등을 전문가와 검토한다. 반복 노출·도움말 사용이 섞인 표본을 구분한다.
- **완료 기준:** 사전에 정한 지표·표본 조건·관찰 기간·조정 이유를 보고한다. 데이터가 부족하면 '검증 중'으로 남긴다. 실제 한능검과 동등한 변별력이나 합격 예측 성능은 검증 근거가 있을 때만 주장한다.

### P2-07 · 전 범위 베타 출시 판정

- 선언한 범위의 개념 누락, 승인되지 않은 문항/이미지, 학습·평가 계열 오염, 기록 보존, 모바일 접근성을 최종 점검한다. 복구할 수 있는 빌드·콘텐츠 버전을 남긴다.
- **완료 기준:** 전 범위 콘텐츠·기능 게이트와 미검증 평가 항목을 분리한 출시 보고서가 있다. 실측이 부족하면 베타/연습용 한계를 정확히 표시한다. '시험 공부를 이 서비스만으로 끝낼 수 있다'는 주장은 콘텐츠 양만으로 승인하지 않는다.

## 7. 자동화와 문서를 계속 최신으로 유지

### Q-01 · 자동 감사의 실제 검사 범위 확장

- 기존 [감사 스크립트](../scripts/automation/audit.mjs)와 [운영 문서](automation.md)를 재사용한다. P0-03 및 PR #8 통합으로 데이터 구조가 바뀌면 AST 파서/어댑터를 함께 수정한다.
- 개념 매핑·출처·이미지 승인·문항 상태·계열·출제 기준별 부족을 기계적으로 검사 가능한 범위에서 추가한다. 기존 경고 해소와 새 콘텐츠 승인 정책을 구분하고 단계적으로 차단 규칙을 강화한다.
- **완료 기준:** 새 구조에서 실제 수량을 읽으며 누락/미지원 구조가 조용히 통과하지 않는다. 오류·경고·수동 검수 필요를 구분하고 의미 있는 규칙 테스트를 갖춘다. 역사적 진위·학습 효과는 자동 승인하지 않는다.

### Q-02 · 변경마다 작업 원본과 운영 상태 갱신

- PR에 작업 ID, 기준 SHA, 수용 기준 증거, API/이전 영향, 미해결 사항을 적는다. 정책/API가 바뀌면 이 문서와 계약/brief/AGENTS/Cursor 규칙 중 영향을 받는 문서를 함께 고친다.
- 정기 점검은 새 PR HEAD·새 실패·일정 변경·조치 필요만 알리고 동일 상태를 반복 보고하지 않는다. 공식 일정 변경을 발견해도 사용자의 목표나 운영 데이터를 자동 변경하지 않는다.
- **완료 기준:** main/작업 브랜치/미병합 PR/공개 배포가 구분되고 완료 표시는 증거와 연결된다. 자동 병합·자동 배포는 현재 설치 범위에 포함하지 않는다. 브랜치 보호·필수 검사 정책은 통합 브랜치 정리 후 별도로 검토한다.

## 8. 총괄과 Cursor의 역할, 다음 실제 작업

| 역할 | 맡길 일 | 검수 방식 |
|---|---|---|
| 총괄(Codex 권장) | P0 PR 비교·제품 정책·E 공통 기반·기록 이전·G 검수 기준·통합·배포 판단 | API와 데이터 보존을 직접 검수하고 완료 근거 승인 |
| Cursor | 확정된 API를 사용하는 B → C/F → D의 경계가 명확한 구현 묶음 | B를 첫 파일럿으로 보고 수용 기준 통과 후 병렬 범위를 확대 |
| 콘텐츠 작업 | G 원본 수집·개념 구성·문항 초안·출처 표·에셋 준비 | AI 초안과 사실/권리/정답 유일성 승인을 구분 |

Cursor의 결과 품질은 도구 이름만으로 보장하지 않는다. 기존 코드를 읽고, 작은 범위·확정 API·구체적인 수용 기준을 제공하고, 실제 동작과 데이터 보존으로 판단한다. 하나의 프롬프트에 모든 서비스를 독립 구현하도록 넣지 않는다.

다음 실행 묶음은 **P0-01과 P0-02**다. 그 결과를 바탕으로 E 계약을 구현·검증한 뒤 B를 배정한다. C/F는 E 계약과 B 검수 뒤 별도 작업 디렉터리에서 진행할 수 있다. G의 자료 조사는 독립 산출물로 진행하고 공통 스키마 변경은 E와 조정한다. 현재 문서 작성만으로 이 배정이 실행되지는 않는다.

각 작업 종료 시 이 문서의 상태를 바꾸고 **완료 커밋/PR·검증 결과·잔여 의존성**을 함께 기록한다. 계획을 추가한 커밋 자체를 제품 작업 완료로 표시하지 않는다.

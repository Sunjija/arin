## 의존성과 범위
PR #12/#11/#8의 타입·서비스·DB를 비교하고 재사용·충돌 목록부터 작성한다.
공유 타입·DB·API·CSS는 총괄 계약을 따른다. 문서의 목표 기능을 구현 완료로 가정하지 않는다. 소유 경로 밖의 변경은 의존성으로 보고한다.

## 요구 사항
- 목표/개념/시도/복습/세션의 실제 타입·API 경로·인자·반환값·에러와 소비 예제를 확정.
- 완료 기반 진도·결석 재계획·시험일/완주일·학습 요일 구현.
- 자료실·오늘·복습 기록 통합. 단순 열람·학습 완료·숙련 분리.
- 새 단원 풀과 배운 범위의 누적 복습 풀 분리. 최근 오답 ID를 복습 도래 ID와 동일 취급하지 않는다.
- 고정 시간 분량·일괄 속도 감점 전환. 구형 필드·백업의 명시적 이전.

## 수용 기준
기존 DB/백업/편집 카드/세션/모의 답안 보존, 실패 원자성, 재시도·중복 제출. 검증 후 B/C/F 계약 동결.

## 제출
기준 SHA, 변경 파일, 계약/이전 영향, 기존 PR 재사용 결정, 수용 기준별 증거, 검증 명령·결과, 남은 실패, 커밋/PR을 제출한다. 미실행 검증과 배포 여부를 명시한다.

## 80% 목표의 판단 기준과 남은 작업

**이번 코드 개선만으로 전체 출시 품질 80%에 도달했다고 판정하지 않는다.** 다음은 작업 완료 게이트이며 사용자 학습 효과의 백분율이 아니다. 이전 10문항의 약 49% 평가는 주관적인 편집 평가로만 유지한다.

1. 핵심 흐름: 학습 시작/이어하기/복습/모의고사/기록/백업의 회귀 테스트와 타입/린트/빌드 통과. 이번 통합으로 개선.
2. 콘텐츠: 내부 개념 목록의 최소 80%인 **71/88개**에 출처 확인 설명+회상+명시적 확인 문제를 갖추고, 순서 중간 공백 없이 학습 가능해야 함. 71개라는 운영 목표도 공식 전 범위 완성이나 실제 학습효과를 뜻하지 않음. 앱 출시에서는 최종 전체 범위 공백도 별도 판단해야 함.
3. 평가: 제작/검수 상태와 실제 이용 조건을 추적하고 승인된 실전 세트를 구성해야 함. 최근 기출 65–79회 분석 범위를 회차/번호로 증명하고 확인된 데이터에서 목표 비율을 산출해야 함. 현재의 임시 배점·시대·유형 목표와 별개.
4. 실제 앱: 최신 제품 코드를 Android/iOS 패키지에서 실행하고, 저장 후 강제 종료/재실행·앱 업데이트·백업 복구·네트워크 단절을 실기기로 통과해야 함.
5. 출시 운영: 선택한 계정/동기화 모델의 데이터 소유권, 탈퇴/삭제/복구, 오류 접수, 개인정보 안내, 스토어 제출 자료를 준비해야 함. 유료 출시면 인앱 구매/복원/서버 검증이 추가 게이트.

현재 가장 큰 공백은 화면 디자인이 아니라 **학습 콘텐츠와 사람 검수, 실기기 저장 검증**이다. 대규모 문항 생성이나 결제 화면 추가를 위 게이트 대신 완료율에 합산하지 않는다.

우선순위와 분업:

- **P0 콘텐츠**: 다음 미준비 개념부터 작은 묶음으로 설명/기초 확인/비교 문제를 작성. 정답 유일성·출처·해설을 별도 검수하고 버전을 올림. 오래된 스냅샷 불변 테스트 유지.
- **P0 앱 패키지**: `origin/work/mobile-app`과 최신 제품을 비교해 필요한 셸만 이식. Android/iOS 실기기 시험과 앱 업데이트 시 로컬 데이터 보존을 담당. 기존 화면/API와 병렬 가능.
- **P1 문항 검수·패턴 근거**: `origin/cursor/exam-pattern-research-b248`, `origin/cursor/mock-exam-quality-1da6`의 자료를 증거 단위로 재사용. 이전 q-57 등 10문항 개선 지시가 별도 작업 중이면 덮어쓰지 않고 완료 커밋을 검토하여 반영.
- **P1 계정/운영**: 기존 account-sync 브랜치의 소유권·로그아웃·기기 변경·충돌·복구 테스트를 최신 DB 계약에 맞춰 이식. 로그인했다고 로컬 진도를 자동 업로드하거나 다른 계정으로 귀속하지 않음.
- **P2 결제**: 무료 학습 루프와 콘텐츠/실기기 검증 후, 선택한 플랫폼의 구매·구독·복원·환불·권한 동기화 설계. 이번 통합에는 결제 기능을 넣지 않았다.
